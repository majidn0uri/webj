# تکمیل زیرساخت پنل پس از بازطراحی — ۲۰۲۶/۰۹/۲۲

## اصلاح‌ها

- ۳۷ خطای نوع ریشه و دو خطای اسکریپت‌ها رفع شدند، بدون `@ts-ignore` یا خاموش‌کردن دروازه‌ها.
- نگهبان شمارش/انتقال انبار اکنون واقعاً `inventory.read/write` را بررسی می‌کند. مغایرت بانکی و سن بدهی نیز آرگومان صحیح `accounting.read/write` را به نگهبان می‌دهند.
- PDF درخواست خرید از `@set/exports` و قرارداد `InvoiceSpec` استفاده می‌کند؛ ارجاع به فایل ناموجود حذف شد.
- PDF مرجوعی سفارش و اقلام را از قرارداد واقعی `getReturn` می‌خواند؛ جمع مبلغ چندعددی را تکرار نمی‌کند و وضعیت «پرداخت‌شده» را جعل نمی‌کند.
- CRM: UUID معتبر برای تعامل، تطابق nullableهای API، خواندن قواعد jsonb بدون parse دوباره و نوع‌گذاری خروجی آمار/پرونده مشتری.
- مرسوله‌های حساب مشتری بر اساس شماره سفارش **و صاحب سفارش** خوانده می‌شوند، نه شناسه‌ای که در پاسخ سفارش وجود ندارد.
- قرارداد تخفیف حجمی سبد بدون cast نامعتبر استفاده می‌شود. چک در checkout فیلد و اعتبارسنجی شناسه صیاد ۱۶ رقمی دارد و مقدار null به ستون NOT NULL ارسال نمی‌شود.
- تنظیم ناشناخته `static` از افزونه فشرده‌سازی حذف شد؛ فیلتر محتوای پیش‌فرض افزونه حفظ شده است.
- اسکریپت یادآوری از قرارداد مشترک پایگاه استفاده می‌کند و اتصال را حتی هنگام خطا می‌بندد؛ تشخیص نشانی رسانه نیز با strict TypeScript هم‌خوان شد.
- آزمون تأمین رکوردهای تاریخچه قیمت متعلق به تأمین‌کننده آزمون را پیش از پاک‌کردن آن حذف می‌کند. شکست قبلی در teardown بود، نه ۹ سناریوی تأمین.

## مهاجرتِ نصب‌های قبلی

`039_shipping_checks_permissions.sql` بدون تغییر SQL به `049_shipping_checks_permissions.sql` منتقل شد. تعداد فایل‌ها همچنان **۴۹** است و شماره‌ها یکتا و پیوسته‌اند.

اگر نصب قبلی نام قدیمی را در `schema_migrations` دارد، runner فقط نام جدید را ثبت می‌کند و نام تاریخی را نگه می‌دارد؛ SQL اعطای مجوز دوباره اجرا نمی‌شود. پس مجوزی که مدیر عمداً لغو کرده برنمی‌گردد. برای نصب تازه SQL در جایگاه ۰۴۹ اجرا می‌شود. نیازی به حذف پایگاه یا بازنشانی تاریخچه نیست.

## نتیجه سنجش محلی

- `npm run verify`: موفق؛ typecheck ریشه، وب، اسکریپت‌ها و بازرس؛ **صفر خطا** و یک هشدار قدیمی ایمیل.
- `npm run build:web`: موفق.
- `npm run template:check`: موفق؛ طراحی و قالب خودکفا هم‌خوان‌اند.
- `npm test`: **۸۷۵ آزمون، ۶۲ پرونده، همه موفق**؛ حدود ۸۵۰ ثانیه با سرویس‌های پیش‌نمایش خاموش. هیچ فایل آزمونی حذف یا skip نشد.
- ۱۵ آزمون تازه: ۶ نگهبان دسترسی، ۲ قرارداد PDF، ۵ عملیات CRM روی PGlite و ۲ مهاجرت نصب تازه/قدیمی.
- `git diff --check`: موفق.

## باقی‌مانده‌ها

- `npm audit`: ۱۶ آسیب‌پذیری وابستگی موجود، شامل ۱۰ متوسط، ۵ شدید و یک بحرانی. هیچ وابستگی یا lockfile تغییر نکرده؛ ارتقا نیازمند بررسی سازگاری مستقل است.
- آزمون‌های پایگاهی این اجرا با PGlite انجام شدند؛ نتیجه معادل آزمون استقرار روی PostgreSQL واقعی، درگاه بانکی یا سرویس پیامک زنده نیست.
- تغییر شناسه صیاد به معنی ممیزی کامل تراکنش/سقف اعتبار و چک در checkout نیست؛ این جریان مالی نیازمند آزمون انتهابه‌انتهای جداگانه است.
- بازطراحی و رفع موانع روی شاخه جلسه است؛ ادغام با main یا استقرار تولید انجام نشده است. نتیجه CI در PR شماره ۳۹ ثبت می‌شود.
